# Checkpoint sources: Units 7–12

Official pages each checkpoint challenge was checked against on 2026-10-21.
Every page listed was opened on doc.rust-lang.org (the Book, the Reference and
the std docs; the std pages were the 1.99.1 version, while the solutions were
compiled with the pinned `rustc 1.97.0`), and the specific sentence or example
behind each Rust claim in the challenge text, and behind each standard library
item used by the solution, was found on it. The solutions were also compiled
and run with `rustc --edition 2024 -C opt-level=1 -C overflow-checks=on`
(through `tool/check_lessons.py`), and the functions were called with extra
inputs in throwaway `#[test]` modules. Compiler checks alone were not treated as
enough: the pages below are the source for what the text says.

Things to know:

- The std `Debug` page says that the `Debug` output of standard library types
  is not stable (https://doc.rust-lang.org/std/fmt/trait.Debug.html#stability).
  The challenges print only `Vec`, tuple, `Option` and quoted-`str` output with
  `{:?}` (the same shapes the earlier lessons already show), never `Debug`
  output of a struct. `tool/check_lessons.py` fails if the compiler's output
  ever changes.
- The Collatz numbers printed by u8-check (111 steps and a peak of 9232 for the
  start value 27) are maths, not Rust. They were checked against the OEIS:
  https://oeis.org/A006577 (halving and tripling steps; the 27th term is 111,
  and the challenge prints 112 items because the start value counts) and
  https://oeis.org/A025586 (largest value in the trajectory; the 27th term is
  9232).
- The statement "the app skips `#[cfg(test)]`" in u9-check is about this app's
  runner, not Rust. It compiles one file with plain `rustc` and no `--test`
  flag (see `RUSTC_FLAGS` in `tool/check_lessons.py` and `runner/src/sandbox.rs`).
  The Rust side is the `test` option in the Reference, cited below.
